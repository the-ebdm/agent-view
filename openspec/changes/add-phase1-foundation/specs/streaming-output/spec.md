# Streaming Output Specification

## ADDED Requirements

### Requirement: Real-time SSE Streaming
The system SHALL provide a Server-Sent Events (SSE) endpoint that streams agent messages in real-time.

#### Scenario: Establish SSE connection for running agent
- **WHEN** a GET request is made to `/api/agents/{id}/stream` for an active agent
- **THEN** the system establishes an SSE connection with Content-Type "text/event-stream"
- **AND** begins streaming messages as they are generated by the agent

#### Scenario: Stream message format
- **WHEN** the agent generates a message
- **THEN** the system sends an SSE event with JSON data
- **AND** the JSON includes message type, content, and timestamp
- **AND** the message type is one of: "assistant", "tool_use", "tool_result", "result", "error"

#### Scenario: SSE connection to non-existent agent
- **WHEN** a GET request is made to `/api/agents/{id}/stream` with an invalid agent ID
- **THEN** the system returns a 404 error
- **AND** does not establish an SSE connection

#### Scenario: SSE connection completes when agent finishes
- **WHEN** the agent completes execution or encounters an error
- **THEN** the system sends a final message with type "result" or "error"
- **AND** closes the SSE connection gracefully

### Requirement: Structured Message Display
The system SHALL display agent messages in a structured format showing both message types and formatted content.

#### Scenario: Display assistant messages
- **WHEN** an agent sends a message with type "assistant"
- **THEN** the UI displays the message with an "Assistant" label
- **AND** renders the content as formatted markdown

#### Scenario: Display tool usage messages
- **WHEN** an agent sends a message with type "tool_use"
- **THEN** the UI displays the message with a "Tool" label
- **AND** shows the tool name and parameters

#### Scenario: Display tool result messages
- **WHEN** an agent sends a message with type "tool_result"
- **THEN** the UI displays the message with a "Result" label
- **AND** shows the tool output

#### Scenario: Display error messages
- **WHEN** an agent sends a message with type "error"
- **THEN** the UI displays the message with an "Error" label in red
- **AND** shows the error message and details

### Requirement: Auto-scroll to Latest Message
The system SHALL automatically scroll the output display to show the most recent message as new messages arrive.

#### Scenario: Auto-scroll on new message
- **WHEN** a new message is received via the SSE stream
- **THEN** the output display automatically scrolls to show the new message
- **AND** the new message is visible at the bottom of the display

#### Scenario: Preserve manual scroll position
- **WHEN** a user manually scrolls up to view earlier messages
- **THEN** the system stops auto-scrolling
- **AND** new messages arrive without changing the scroll position
- **AND** shows a "New messages" indicator at the bottom

#### Scenario: Resume auto-scroll when at bottom
- **WHEN** a user scrolls back to the bottom of the output display
- **THEN** the system resumes auto-scrolling for new messages

### Requirement: Markdown Content Rendering
The system SHALL render assistant message content as formatted markdown with proper styling.

#### Scenario: Render markdown headings
- **WHEN** an assistant message contains markdown headings (# ## ###)
- **THEN** the UI renders them as HTML heading elements with appropriate styling

#### Scenario: Render code blocks
- **WHEN** an assistant message contains fenced code blocks
- **THEN** the UI renders them with syntax highlighting
- **AND** provides a copy button for code blocks

#### Scenario: Render inline code
- **WHEN** an assistant message contains inline code with backticks
- **THEN** the UI renders them with monospace font and background styling

#### Scenario: Render markdown links
- **WHEN** an assistant message contains markdown links
- **THEN** the UI renders them as clickable hyperlinks
- **AND** opens links in a new tab with rel="noopener noreferrer"

### Requirement: Message History Persistence
The system SHALL store all messages for each agent run in memory for later retrieval.

#### Scenario: Store messages during streaming
- **WHEN** messages are received via the SSE stream
- **THEN** the system appends each message to the agent's message history
- **AND** maintains the message order

#### Scenario: Retrieve complete message history
- **WHEN** a user views a historical agent run
- **THEN** the system displays all messages from that run in order
- **AND** includes all message types (assistant, tool_use, tool_result, result, error)

### Requirement: SSE Connection Error Handling
The system SHALL handle SSE connection errors gracefully and provide user feedback.

#### Scenario: SSE connection fails
- **WHEN** the SSE connection to `/api/agents/{id}/stream` fails
- **THEN** the UI displays an error message "Connection lost"
- **AND** provides a "Reconnect" button

#### Scenario: Reconnect after connection failure
- **WHEN** the user clicks the "Reconnect" button after a connection failure
- **THEN** the system attempts to re-establish the SSE connection
- **AND** resumes streaming from the last received message

#### Scenario: Agent completes before SSE connection established
- **WHEN** an SSE connection is requested for an agent that has already completed
- **THEN** the system returns the complete message history immediately
- **AND** closes the connection after sending all messages
